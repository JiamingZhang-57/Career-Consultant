Build a conversational AI assistant using one of the following options:

## Option 1: Chat With Your Docs
Build a system that answers questions about content from a document collection (PDFs, text files, or any format you choose). Classic RAG use-case.

## Option 2: Code Documentation Assistant
Build a system that ingests a codebase (GitHub repo or local files) and answers questions about the code — how it works, where functionality is implemented, API endpoints, dependencies, etc.

## Option 3: Meeting Intelligence System
Build a system that analyses meeting transcripts and answers questions about discussions, decisions, and action items. Transcripts should be text files with speaker labels and timestamps. Optional bonus: voice-to-transcript capability.

## Option 4: Career Intelligence Assistant
Build a system that analyses resumes against job descriptions. Upload a resume and multiple job postings, then answer questions about fit, skill gaps, experience alignment, and interview preparation.

> Example queries: "What skills am I missing for this role?", "How does my experience align with Job #2?"

Choose the option that excites you most. We care as much about **how** you build it as **what** you build.

## What to Submit

1. **GitHub repo** with your code
2. **README.md** with:
   - Quick setup instructions
   - Architecture overview (a simple diagram is great but not required)
   - What would be required to productionise your solution and deploy it on a hyper-scaler (AWS / GCP / Azure / Cloudflare)?
   - RAG/LLM approach & decisions: LLM, embedding model, vector database, orchestration framework, prompt & context management, guardrails, quality, observability
   - Key technical decisions you made and why
   - Engineering standards you followed (and any you skipped)
   - How you used AI tools in your development process
   - What you'd do differently with more time
   - _Note: We need your thoughts, not an LLM's direct output_
3. **Screenshots** of your application (a short video is a bonus)

## What We're Looking For

- **Tech stack** — choose something you could productionise
- **Core functionality** — working Q&A over documents via RAG or similar
- **Creativity** in UI/UX design and product innovation
- **Engineering excellence** — clean, readable, well-structured, ideally containerised and observable code
- **AI-assisted development** — we're interested in *how* you use AI coding tools, not just that you used them

## Tips

- A basic working version with great engineering beats a complex broken one
- Document edge cases you didn't handle rather than papering over them
- **We value a solid, well-engineered basic solution far more than an over-engineered complex one**
